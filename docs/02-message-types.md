# 消息类型编码

## local_type 是复合值

```
local_type = base + sub_type × 2^32
```

拆开：

```js
const base = local_type % 4294967296
const sub  = Math.floor(local_type / 4294967296)
```

只用 `base` 分发，49 类卡片（链接、引用、转账……）就全都变成「未知类型」了。
这是最容易踩的一个坑，而且不报错，只是内容悄悄丢光。

## base 取值

| base | 含义 | 正文在哪 |
| --- | --- | --- |
| 1 | 文本 | 直接是文字 |
| 3 | 图片 | 无正文，附件在 media 目录 |
| 34 | 语音 | 无正文 |
| 42 | 名片 | appmsg |
| 43 | 视频 | 无正文 |
| 47 | 表情 | 无正文 |
| 48 | 位置 | appmsg |
| 49 | 应用消息 | `<msg><appmsg>` 里的 XML |
| 50 | 通话 | 无正文 |
| 10000 | 系统消息 | `<sysmsg>` 里的 XML |

## 引用消息的正文在哪

引用（`sub = 57`）的正文不在 `<content>`，而在 `<refermsg><content>` 里，
外层 `<title>` 只是「某某引用了一条消息」的提示。
直接取 `<des>` 会拿到空串。

## 系统消息要不要导出

`base = 10000` 是撤回、拍一拍、入群提示这类。
它们对读对话没有意义，导出时直接跳过（`src/export.mjs` 里过滤 `[系统]` 前缀）。
要注意：跳过之后「原始条数」和「导出条数」会对不上，这是故意的，头部会把两个数都写出来。

## 群聊的发送者

群消息的正文以 `wxid_xxx:\n` 开头，`real_sender_id` 只指向群本身。
所以要先剥前缀、拿到真实发送者，再拿他查备注名。
非文本消息（图片、表情）没有前缀，`real_sender_id` 才指向真人。

## 文本字段可能是压缩的

`message_content` 是 BLOB：

- `WCDB_CT_message_content = 4` → 内容是 zstd 压过的
- 否则是 UTF-8 明文

实际数据里存在标记没跟上的行，所以两条都判：

```js
if (compressType === 4 || looksZstd(raw)) return zstdDecompressSync(raw).toString('utf8')
```

zstd 魔数是 `28 B5 2F FD`。
