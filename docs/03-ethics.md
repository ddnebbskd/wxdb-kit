# 使用边界

这个工具能解开本地加密库，所以更要写清楚它应该被用在哪。

## 可以

- 导出**你自己账号**在**你自己设备**上的聊天记录
- 换机、换系统、客户端不再支持导出功能时的数据保全
- 研究本地存储格式本身
- 在你自己的、你自己有权限的测试环境里验证加解密实现

## 不可以

- 读别人设备上的库
- 读别人账号在同机上的数据（同一台电脑上换号登录也算别人的数据）
- 把导出的内容发布、传播、或用于培训模型后公开发布
- 绕过别人的密码、锁屏、二次验证

第二类在《刑法》第 285 条（非法获取计算机信息系统数据）、
《个人信息保护法》和《民法典》隐私权条款下都可能构成违法，
不因为「我知道密码」而变得合法。

## 本仓库不做的事

处于同样的理由，这个仓库**不包含**密钥提取的实现：

- 不读进程内存
- 不做 DLL 注入
- 不抓网络流量

密钥怎么得到，取决于平台和客户端版本，也取决于你有没有权限拿。
这一段留给你自己判断，本仓库只从「已经拿到密钥」开始。

## 只读

所有代码路径都不写回原始文件：

- 解密结果永远写到新文件
- 数据库以 `readOnly: true` 打开
- 不做 `VACUUM`、不做 `REINDEX`、不删任何东西

原始库被改坏的后果不可逆，这一点没有例外。

## 关于写进简历

如果把这个项目放进作品集，建议同时保留这一段文档。
面试官关心的不只是「能不能解开」，
还有「你知不知道它该被用在哪」——
后半句往往比前半句更能说明水平。
