# wxdb-kit

微信 4.x 桌面端本地数据库的**离线解析与导出**工具链。

用 Node 标准库写成，零第三方依赖，只读。仓库里所有演示数据都是程序合成的，不含任何真实账号或聊天内容。

---

## 这是什么

微信桌面端把聊天记录存在本地 SQLite 库里，但库是加过密的（WCDB，SQLCipher 变体），
消息体还被 zstd 压过，表名是 `md5(对方微信号)`。

这个工具做的就是把这条链路走通：

```
加密库 → 页面解密 → 打开 SQLite → 还原字段编码 → 解析消息类型 → 导出成可读文本
```

它解决的是**解析**这一段。密钥怎么拿到，取决于平台和版本，不在本仓库范围内
（见 `docs/03-ethics.md`）。

## 能做什么

- 校验一把密钥对不对（HMAC + 文件头双重校验，不会「似乎解开了」但其实解错了）
- 整库解密到副本，原始文件一个字节都不动
- 按 `md5(username)` 反查消息表属于谁，包括分片库里各自独立的 `Name2Id`
- 还原被 zstd 压过的字段：靠 `WCDB_CT` 标记，也兼容标记缺失时认魔数
- 解析 `local_type` 的复合编码，把链接、引用、转账、红包、聊天记录、系统消息分开
- 导出成按天分段的纯文本，或结构化 JSON
- 用 CDP 在已登录的浏览器里做只读取数（`src/cdp.mjs`，不依赖 puppeteer）

## 不做什么

- 不提供、也不实现密钥提取（不读内存、不做注入、不抓包）
- 不解图片、语音、视频、文件这些附件本体，只记录「这里有一张图」
- 不写回、不改库、不碰 `wal` 之外的原始文件
- 不对接任何在线服务，全程离线

## 快速开始

需要 Node ≥ 22.5（用到内置的 `node:sqlite` 和 `zstd`）。

```bash
npm run fixture   # 生成合成的演示库（加密过）
npm run demo      # 解密 → 解析 → 导出，并自检
```

跑完应该看到：

```
密钥校验：通过
解密完成：5 页 → out/demo.db
阿岚：27 条原始，导出 26 条
  类型分布：{"1":19,"3":1,"34":1,"43":1,"47":1,"49":3,"10000":1}
自检：
  文本：命中
  zstd 压缩字段：命中
  引用：命中
  转账：命中
  系统消息已过滤：正常
```

产物在 `out/`：`demo.db`、`阿岚.txt`、`项目组.txt`、`阿岚.json`。

## 三个真的坑

**1. `local_type` 不是小整数。**
它等于 `base + sub_type * 2^32`。用 `switch (local_type)` 直接分发，
所有 49 类卡片的子类型都会掉进 default，链接、引用、转账全变成「未知类型」。
正确写法是先取余、再整除。

**2. 压缩字段的标记会缺席。**
长文本存进 `message_content` 前会被 zstd 压过，`WCDB_CT_message_content = 4` 表示压过。
但实际数据里存在标记没跟上的行，所以判断条件要两条一起看：标记为 4，**或者**内容以 zstd 魔数
`28 B5 2F FD` 开头。

**3. 分片库的 `Name2Id` 是各自独立的。**
`message_0.db` 和 `message_4.db` 各有一份自己的 `rowid → username`，
混用会把发送者指到别人身上。

## 已知限制

- `wal` 里尚未落盘的帧可能缺；本实现只统计了帧数，没有做强一致重放
- 语音只标类型，不做转写
- 群成员昵称需要另外读 `chat_room` 的 `ext_buffer`
- 每页 4096 字节、保留区 80 字节：换了内核版本要重新核对，不是长期稳定契约

## 免责
